3 · What would have been simpler as one agent with tools

  • Ticket 102 is the clearest example. The whole job is get_ticket → get_lease(1) → list_payments(rent, 1) → get_cash_balance → list_open_invoices. One agent holding those tools does that in about 3 model calls. The team used 9, and the boss spent 15.6k tokens just reading and repackaging two reports. Meaning also blurred in the hand-off: facilities' hedge "can't fully verify" became the boss's reason not to prepare a cheque at all.
  • The duplicates in 101 and 103 only exist because the agents have separate memories. A single agent would never call check_stock(CC-HOOD-NAVY, M) twice in one job. It would already know the answer.
  • Customer Service called only get_ticket on both 101 and 103. Its job was writing, not looking anything up. A single agent can draft "Hi Tauhid, we have M, L, or XL…" in the same breath.
  • The $160 problem spans two tickets (invoice 501 on 101, rent on 102). Our team runs one ticket at a time, and each run starts with an empty head. One "desk agent" working all open tickets in one pass would see both bills together. The tools for that already exist (list_open_invoices plus list_leases); it's the split that hid it.
  • What the team did buy us:
    • shorter, focused prompts (Facilities' rent rules don't clutter Customer Service's tone rules),
    • a readable "who did what" story on the board,
    • least privilege (only the boss has update_ticket; Customer Service can't see cash).
    But the real safety came from the tool layer: no MCP tool can move money, and POST /payments/approve re-checks amount, bill status, and balance. That would protect a single agent just as well.
  • My verdict: for three tickets this size, one agent with the 15 MCP tools would be simpler, faster, and cheaper. My rough estimate is a third to half the tokens; I haven't measured it. Multiple agents start to earn their keep when roles need different permissions or there's real parallel volume, like a September rush with 50 tickets a day.

Close the sale when Tauhid says "I'll take an M"

Confirm the rent with the landlord (ticket 102's blocker)

Build: get_email(message_id) returning headers, sender domain, and attachments; contact_email / contact_phone columns on leases, taken from the signed lease; and an approval-gated send_message so Facilities can ask "please confirm $2,400 due 9/02", but only to the address already on file, never one taken from the email.
